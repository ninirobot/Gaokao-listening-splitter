# 高考英语听力 · 自动切分工具

**把一整份高考真题/模拟题听力 MP3 丢给它，它按时间顺序把里面的材料一段一段切出来，
命名成 D01、D02……每段只保留第一遍。**

---

## 先说清楚它走的是什么路子

这个工具是**纯代码实现的，不借助任何 AI**：

- 不做语音识别，不转文字，不理解英文讲了什么；
- 不联网、不上传，在你自己电脑上运行完就结束；
- 只靠「波形结构」做判断——哪里是静音、哪两段声音一模一样。

之所以坚持这条路线，是因为现在常见的做法都要先把音频转成文字、再让 AI 去判断
哪里是一段，又重又慢，还依赖网络和接口。而听力录音本身的结构非常规整：
**同一段材料播两遍，两遍通常是同一份音频的复制粘贴**——这一点靠波形就能抓到，
根本用不上 AI。

## 一、怎么用

### 方式 1：放在同一个文件夹里双击

1. 把 exe 和听力 MP3 放在同一个文件夹里；
2. 双击 exe；
3. 等它跑完（一份 MP3 大约 5 秒），按回车关窗口；
4. MP3 旁边会多出一个「MP3 同名 + `-切分结果`」的文件夹，里面就是切好的材料。

一个文件夹里放多份 MP3 也可以，它会依次全部切完。

### 方式 2：把 MP3 拖到图标上

把 MP3（可以多选几个）直接拖到 exe 图标上松手，就只切这几个文件，
不需要和 exe 放在同一个文件夹里。

### 方式 3：命令行（想批量跑、或不想让它暂停时）

```
python scripts-v3/split-listening-v3.py <文件或文件夹> [--no-pause] [--format=5+5]
```

| 参数 | 作用 |
| --- | --- |
| `--no-pause` | 跑完直接退出，不等你按回车 |
| `--format=5+5` | 改节数：前面是「播一遍」的段数，后面是「播两遍」的段数。一般不用动 |

### 环境要求

- **exe 版**：什么都不用装，双击即用（ffmpeg 已经打进 exe 里了）。
  注意 exe **不在仓库里**，是本地打包出来的，打包方法见第七节；
- **脚本版**：需要 ffmpeg。命令行里能直接敲 `ffmpeg` 就行；没有的话执行
  `pip install imageio-ffmpeg` 再运行。
- 只处理 `.mp3` 输入，其它格式请先转成 MP3。

### 会产出什么

```
你的听力MP3.mp3
你的听力MP3-切分结果/
    D01.mp3
    D02.mp3
    ...
    D10.mp3
    timeline.json
```

- `D01.mp3` … `D10.mp3`：切好的材料，按卷子里的先后顺序编号，**每段只留第一遍**；
- `timeline.json`：每段的起止秒数、可信度等，是给后续做「听力精讲网页」之类用的，
  平时不用管它。

## 二、能力边界：能做什么，不能做什么

### 能做的

- 把整卷听力 MP3 按顺序切成一段一段，命名 D01 起，每段只保留第一遍；
- **两种朗读规则都能处理，而且不需要你声明是哪一种**，程序自己判断并写在屏幕上：
  - 旧规则：第一节 5 段播一遍 + 第二节 5 段播两遍；
  - 新规则：第一节也播两遍，10 段全是播两遍。
- 不需要安装任何软件，双击就能用；
- 每段自带可信度自检，并且明确指出哪一段值得你单独听一下；
- 被丢弃的内容会逐条写明原因，不静默丢东西；
- 遇到不标准的录音结构，照实报出来，不硬凑段数。

### 不能做的

- **不做语音识别**，不理解英文内容。它只认波形和静音，所以「这段讲的是不是第 6 题」
  这类语义问题一律不判断；
- **不切题干和选项**（q01–q20 那类定位句），本工具不做这部分；
- **不做跨卷响度归一化**。同一份卷子内部音量是一致的，只有把多份卷子拼到一起时
  才需要做；
- 只处理 `.mp3`；
- 边界精度是**秒级**：正常情况误差在零点几秒。但如果某份录音里播报和材料之间
  几乎没有停顿，机器就分不开，这种只能人工核一下那一段；
- 专项训练这类「一份音频里塞了十几二十段材料」的制品也能切，只是段数不是 10，
  程序会照实写「比标准高考多，按实际的 N 段使用」。

## 三、工作原理

整个流程不看内容，只看波形，一共五步：

### 第 1 步 · 解码

用 ffmpeg 把 MP3 解成波形（8kHz 单声道）。降采样是为了快，对「找静音、比波形」
这两件事来说完全够用。

### 第 2 步 · 按静音切成语音块

音量低于 -35dB 且持续超过 0.6 秒的算静音，其余是有声区间。
于是整卷录音变成一串「语音块 + 间隔」，后面所有判断都在这串上做。

### 第 3 步 · 找「播两遍」的材料（主干）

同一段材料连播两遍，两遍是同一份数字音频的复制粘贴——这是整卷里**最硬的信号**，
比任何音量、时长的经验规则都可靠，所以程序先找它。

做法：按语音块的时长序列，找两处能对上的串（允许「一遍是整块、另一遍被切成两块」
这种常见情况），再用波形比对确认。确认时会把提示音排除在证据之外——提示音是同一小段
反复播放，互相之间天然就很像，拿它当证据会把假配对判成真的。

这一步与「哪一节」无关：旧规则卷在这一步找出第二节的 5 段，新规则卷则一次把 10 段
全找出来。

### 第 4 步 · 找「只播一遍」的材料（剩下的活）

只播一遍的材料没有重复片段可比，只能靠外部线索，程序有两条路：

- **主路：提示音**。高考录音每段材料前有一小段固定乐音（叮咚声），它有三个特征：
  时长 0.6~2.5 秒、频谱几乎不变（是固定乐音不是人声）、整卷反复出现且彼此很像。
  程序先用「频谱平稳性」把人声短语挡在外面，再把剩下的按波形相似度聚类，
  取最大的一簇当提示音，提示音之间的内容就是一段材料。
- **兜底：答题静音**。有些录音根本不放提示音，主路整个失效。这时改用「答题静音」
  来分块：材料之间隔着约 10 秒的答题静音，而材料内部只有 1 秒左右的小停顿，
  按间隔 ≥3 秒切开后，取长度彼此最接近的连续几块（同节的材料长度接近，
  而开场说明、第二节说明都比它们长得多）。

第 3 步已经判为「播两遍」的时间段，这一步整段跳过，不重复处理。
所以新规则卷走到这里已经没活可干——**不需要额外的开关或参数**。

### 第 5 步 · 边界重锚、自检与切分

粗筛出来的配对，边界常常不准：同一段材料两遍的静音切分并不一致，
按「块长对上」找出来的起点可能落在提示音或题目播报上。

所以每一对都要**再用整段波形对齐一次**：求出两遍之间精确的时间偏移，
然后在候选边界附近各搜几块，取「整段最吻合」的那组；两遍之间若还夹着语音块
（同一段材料被切成两截），一并并进第一遍。

对齐之后逐段自检，主要看三个东西：

- **吻合度**：两遍相减后剩下的残差换算成百分比，一模一样是 100%，毫不相干是 0%；
- **两端 vs 主体**：如果多带了只播一遍的东西（题目播报、答题提示），只会让两端变差；
- **卷内离群**：本段和本卷其它段落比，是不是明显差一截，用来抓「这一遍被录音方
  重新录过、或做过变速剪辑」这类情况。

> 为什么不用绝对数值当判据？因为它首先反映的是**这份录音的两遍复制质量**，
> 不同卷子之间能差十倍，拿绝对值卡阈值会把「录音差一点」误报成「切错了」。
> 所以只在**同一份卷子内部**做相对比较。

最后用 ffmpeg 截取，前后各留一点余量并加 0.1 秒淡入，再确认切出来的不是静音。

## 四、屏幕上的字都什么意思

| 屏幕显示 | 含义 |
| --- | --- |
| `找到 10 段材料：第一节 5 段播一遍 + 第二节 5 段播两遍（标准结构）` | 旧规则，正常 |
| `找到 10 段材料：10 段，每段都播两遍` | 新规则，同样正常 |
| `两遍吻合 98%` | 这一段的两遍有多像。越高越干净。**不要拿不同卷子的数字互相比**，只有某一卷里有一段明显低于本卷其它段落时，才值得听一下 |
| `· 跳过 xxx 秒：……` | 被判为「不是材料」而过滤掉的内容，属于正常过滤，每行都写了原因。怀疑漏切时先看这里 |
| `!! 请留意 Dxx：……` | 这一段的边界可能不准，建议单独听一下 |
| `!! 注意：这份录音只找到 N 段……` | 标准高考是 10 段，少于 10 段说明可能有材料没找到，需要核对 |
| `全部切好，N 段的音量都正常` | 一切正常 |

## 五、常见问题

**双击后窗口一闪而过？**
说明那个文件夹里没有 MP3，把 MP3 放进去再试。

**首次双击 Windows 提示「已保护你的电脑」？**
点「更多信息」→「仍要运行」即可。

**我怎么知道它认对了是哪种朗读规则？**
看第一行「找到 N 段材料：……」。写着「10 段，每段都播两遍」就是新规则；
写着「第一节 5 段播一遍 + 第二节 5 段播两遍」就是旧规则。

**切出来的某一段开头/结尾多了一两句播报？**
个别录音的播报和材料之间停顿太短，机器分不开。手动核对那一个文件即可，
绝大多数是准的。

**某一段明显偏短或偏长？**
先看这一段的提示文字，也可以对照 `timeline.json` 里的起止秒数，
用播放器跳到对应位置确认。

## 七、exe 从哪来：GitHub Release

**仓库里不放 exe**——一个约 50MB 的二进制文件不适合进 git。
exe 的分发方式是 **GitHub Release**：本地打包好，作为 Release 的附件传上去；
用的人到 Releases 页面下载即可，不用 clone 代码，也不用装 Python。

### 7.1 本地打包

在**仓库根目录**、用**非管理员**终端执行：

```
pip install pyinstaller imageio-ffmpeg

pyinstaller --onefile --console --name 听力切分-v3 --collect-all imageio_ffmpeg scripts-v3/split-listening-v3.py
```

几点说明：

- `--collect-all imageio_ffmpeg` 是把 ffmpeg 一起打进 exe。PyInstaller 没有自带
  imageio_ffmpeg 的钩子，不加这一项的话，exe 换台电脑就会报「没有找到 ffmpeg」；
- **不要加 `--noconsole`**：本工具要在窗口里打印进度、并等你按回车，隐藏窗口反而用不了；
- 打好的 exe 在 `dist/听力切分-v3.exe`。

## 八、更新日志

### V1 — 2026-09-20 · 首个可用版

打地基的一版，把整条流水线跑通：

- 用静音检测把整卷录音切成一串「语音块 + 间隔」；
- 抓住「同一段材料播两遍 = 同一份音频的复制」这条最硬的信号来找材料，
  并按波形比对确认；
- 用提示音（每段材料前的叮咚声）定位只播一遍的段落；
- 按时间顺序输出 D01–D10，每段只保留第一遍，另附 `timeline.json`。

### V2 — 2026-09-20 · 稳定性修复

V1 在真实卷子上暴露的几个具体毛病，这一版逐个修掉：

- **一整段没有内部停顿的材料也能配对**。有些材料内部一口气念完、整段就是一块，
  原先要求「至少两块」的规则会整段漏掉；
- **碎片对能合并**。两遍的静音切分并不总是一致，同一段材料在一遍里是整块、
  在另一遍里被切成两块时，现在会按相同的时间偏移合并回去；
- **配对端点往外做波形延伸**。修掉了「材料尾部被切掉一截」的问题；
- **音量校验加重试**。切出来的文件刚写完时偶尔会被系统安全软件短暂占用，
  导致音量读不到、被误报成「这一段是静音」，现在会重试几次再下结论。

### V3 — 2026-09-21 · 大版本（主程序重写）

这一版改的是判断方式本身，不只是修修补补：

- **自动适配两种朗读规则**。旧规则（第一节 5 段播一遍 + 第二节 5 段播两遍）和
  新规则（10 段每段都播两遍）都能处理，**不用选版本、不用填参数**，
  程序自己判断并把结论写在屏幕上；
- **段边界改成「两遍波形对齐后重新锚定」**，不再靠块长序列去猜边界。
  以前起点偶尔会落在提示音或题目播报上，现在明显减少；
- **每段给出「两遍吻合 XX%」的自检数字**。只在同一份卷子内部做相对比较，
  明显低于本卷其它段落时才会提醒你核对，不会因为某份录音本身复制质量差就乱报警；
- **新增无提示音录音的兜底**：找不到提示音时改用「答题静音」来分块定位，
  不再出现「第一节一段都没定位到」就束手无策的情况；
- **去掉了新规则卷子上的假警报**。以前第一节播两遍的卷子会被误报成
  「结构和标准高考不一样」，现在两种结构都算正常；
- **段数口径改成「标准高考 10 段」**。多于 10 段的制品（专项训练之类）照实报
  实际段数，不再算失败——不再把「5 段单遍 + 5 段双遍」写死成唯一通过标准；
- 工程结构上把开发脚本、测试样本、打包产物从版本库里分离出去，
  仓库只保留核心主程序。
